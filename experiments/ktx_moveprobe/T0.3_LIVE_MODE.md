# T0.3 — KTX live-brain mode (on-box live loop) — #209

Closes the **live-brain loop** (docs/18 Phase 0, ticket #209): a real KTX bot's
MOVE comes from the MoveMLP sidecar each tick over the T0.2 `/dev/shm` transport,
with a safe staleness fallback so the bot **never freezes**. Aim + fire stay
stock frogbot (Phase 0; the learned aim head is Phase 2). This is the runbook +
the on-box validation evidence.

## The pieces (all merged, in order)

| stage | artifact | role |
|-------|----------|------|
| T0.4 | `scripts/move_world_view.py` | the 6 world-view features — single source of truth |
| T0.6 | `scripts/move_policy_sidecar.py` | loads MoveMLP, reads VIEW, writes MOVE over shm |
| PR-A | `live/` (`move_world_view.{c,h}`, `move_shm.{c,h}`) | C world-view + shm/seqlock unit, CI byte-matched to the Python (`tests/test_live_c_parity.py`) |
| PR-B | `frogbot-moveprobe-live.patch` | KTX **mode 30** (`BotApplyMoveProbeLive`): build VIEW from self-state → write → read freshest MOVE → apply move only, else stock-frogbot fallback |
| PR-C | `frogbot-moveprobe-live-p99.patch` (this) | lightweight on-KTX cost instrumentation (p50/p99/max) + this runbook + evidence |

## mode-30 cvars (per-slot via the existing `_s<N>` plumbing)

| cvar | default | meaning |
|------|---------|---------|
| `k_fb_moveprobe_mode_s<N>` | unset | set to `30` to put bot slot N in live mode |
| `k_fb_moveprobe_live_shm_name[_s<N>]` | `komodo_move_t06` | shared `/dev/shm` region name (must match the sidecar's `--shm-name`) |
| `k_fb_moveprobe_live_stale_ticks` | `3` | freshness window; accept a MOVE answered within this many ticks of the request, else fall back |
| `k_fb_moveprobe_live_log` | off | `1` → throttled `[moveprobe-live] … LIVE/FALLBACK` lines (each carrying cumulative per-frame counters `live=<live_frames>/<total_frames>` for the freshness gate) **and** a periodic (~10 s) on-KTX p50/p99/max cost summary |

`slot = NUM_FOR_EDICT(bot) - 1`. A control/spectator client also takes an edict,
so when adding bots through a client, set mode 30 on all slots (`s0..s3`) — only
real bots reach the seam, so it is safe.

## Runbook (scratch port, live servers untouched)

`run_live.sh` automates the steps below. Always use a **scratch port** (e.g.
28599) and a **scratch gamedir** — never the live `ktx` gamedir / ports
28501–28504 / 28000.

1. Build `qwprogs.so` (patch stack above). Copy it into a scratch gamedir
   (`cp -r <install>/ktx <install>/ktx_t03`; drop the built `.so` in).
2. Launch on the scratch port in matchless FFA so bots roam immediately:
   `screen -dmS qw_28599_t03 -L -Logfile ~/t0.3-run.log ./mvdsv -port 28599 -mem 64 -game ktx_t03 +exec t03_ffa.cfg`
   (`t03_ffa.cfg`: `k_matchless 1`, `k_defmode ffa`, `k_fb_enabled 1`,
   `k_idletime 0`, `k_fb_moveprobe_mode_s0..s3 30`, `k_fb_moveprobe_live_log 1`).
3. `screen -S qw_28599_t03 -p 0 -X stuff "map dm3\r"` then add bots from a
   spectator control client: `python3 qw_min_client.py 28599 --bot-count 2 --spectator`.
4. Start the sidecar (its own venv with CPU torch) attached to the region KTX created:
   `python move_policy_sidecar.py --shm-name komodo_move_t06 --hz 77`.
5. Watch `~/t0.3-run.log` for `[moveprobe-live] … LIVE` + the p99 summary.

## Validation evidence — done-when met (komodo-aws, 2026-06-17, dm3 matchless FFA, scratch port 28599)

The ticket done-when ("1 bot in live mode plays 5 min, no freeze, screen.log
shows live cmds, fallback fires cleanly when the helper is paused") + the plan's
on-KTX p99 — all met on one instrumented run (`evidence/t0.3_live_mode.json`):

- **No freeze.** Server ticked continuously (request counter advancing at ~77 Hz);
  bots fought (frags accrued). KTX owns + zeroes the region on the first live
  frame: `/dev/shm/komodo_move_t06` = **272 B** (the contract size).
- **LIVE cmds.** KTX reads the sidecar's MOVE and applies it, a steady 1-tick
  pipeline delay:
  ```
  [moveprobe-live] slot 1 LIVE fwd=1 side=-1 jump=0 (req=4243 ans=4242)
  ```
- **FALLBACK fires cleanly on pause.** `SIGSTOP` the sidecar → the answer goes
  stale (> stale_ticks) → KTX falls back to stock frogbot, server keeps ticking,
  no freeze:
  ```
  [moveprobe-live] slot 1 FALLBACK (stock frogbot; req=8830 ans=8593)
  ```
- **Resume → LIVE.** `SIGCONT` → the sidecar answers fresh again → LIVE resumes.
- **on-KTX p99 (per-slot).** Per-slot per-tick cost of the live work (build world-view
  + write VIEW + read MOVE + apply); one sample per `BotApplyMoveProbeLive` call,
  11 consecutive ~10 s windows:
  ```
  [moveprobe-live] on-KTX per-slot cost over 1493 samples: p50<=5 us p99<=5 us max=21.1 us (per-slot; frame budget 500 us, <=MSHM_MAX_SLOTS slots/frame)
  ```
  **Per-slot p99 ≤ 5 µs, max 17–83 µs across windows.** The 0.5 ms budget is per
  server *frame*, which services ≤ MSHM_MAX_SLOTS (4) live slots, so the per-frame
  aggregate is ≤ ~4× this ≈ 20 µs — still ~25× under budget. Closes the T0.2 loop on
  the real server (host-local spike p99 ≈ 0.012 ms holds with KTX as the live writer).

## What this is **not**

- Not the frog-vs-leap **verdict** (best-of-N frag margin) — that is **T0.7 (#212)**.
- Not the per-tick **golden parity** proof — that is **T0.5 (#210)** (PR-A front-runs
  the static byte-match in CI).
- The MoveMLP at standstill outputs a near-zero move (a BC-policy fixpoint at zero
  velocity); that is a *policy* property addressed by training (Phase 1+), not a
  loop defect. T0.3 validates that the loop is real, safe, and fast.
