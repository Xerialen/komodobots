## Route isolation is load-bearing — `valid` / `invalid_reasons` (read first)

The whole point of #428 is a **route-ISOLATED** score. If the bot was not isolated on a highway, the
number is meaningless and **must not be consumable**. So `route_eval.v1` carries a top-level
**`valid`** + **`invalid_reasons`**:

- **valid run** = **exactly ONE ENGAGED span** → `valid: true`, `invalid_reasons: []`, the consumable
  `adherence` + `velocity` + `degenerate` are populated (`engaged_window_s` is a single contiguous
  `[t0,t1]`), and the ledger row gets `highway_id`/`rmse_xyz`/`mean_speed_qu_s` + `degenerate` (plus
  the isolation-proof fields `n_engaged_spans`/`engaged_frames`/`engaged_fraction`).
- **invalid run** → `valid: false` + `invalid_reasons`, the consumable
  `adherence`/`velocity`/`degenerate` are **null**, the full-trajectory numbers are quarantined under
  **`non_isolated_debug`** (clearly NOT a score), and the ledger row carries **only** `valid:false` +
  `invalid_reasons` + the isolation fields — **no `rmse_xyz`/`mean_speed_qu_s`**. The reasons:
  - `no_engaged_spans` — the bot never ENGAGED (gate cvar off / never reached a base highway).
  - `multi_span_engagement` — the bot engaged **more than once** (engage → DISENGAGE off-route →
    re-engage). PR1 **fail-closes** here: scoring across the spans would BRIDGE the disengaged gap in
    `velocity`/arclen (and the adherence resample) — a corrupt reward signal. Proper **per-span
    scoring is a deferred follow-up**; until then a multi-span run is invalid.
  - `engaged_window_too_narrow` — the single span maps to `< 2` ticks.
  - `window_extraction_failed` — the windowed decode raised.
  - `player_contact` (**multi-bot only**) — two bots' player **hulls** overlapped (hull-based:
    `|dx|<32, |dy|<32, |dz|<56` — NOT a centre-sphere distance; bots block on ramps/stairs with
    vertically-separated origins) **during the overlap of their engaged windows**: a physics bump
    perturbs the scored path WITHOUT disengaging the gate, which would silently corrupt the MSE, so
    **both** runs fail-closed (no consumable score). See "PR2 — 4 bots / 4 routes".
  - `no_player_bound` (multi-bot only) — a seeded slot bound to no player (binding under-supplied).

  A downstream reader (reward #427, dashboards) must check `valid` first and never read
  `non_isolated_debug` as a result.

(`degenerate` is movement *quality* — a stalled but correctly-isolated run is `valid:true,
degenerate:true`. Isolation and quality are independent.)

## What the metric IS / ISN'T (read first — eval-integrity)

- **adherence MSE/RMSE** (`route_eval.v1.adherence`) = a route-**SHAPE / adherence** proxy vs the ONE
  #420 seed line ("did the bot run THIS highway"). It is **speed-blind** (arc-fraction grid) and is
  **NOT** the optimization target — matching the human centerline would *cap* the bot at human; we
  want it **faster**. It is **NOT** a #421-band believability judgment.
- **velocity** (`route_eval.v1.velocity.mean_speed_qu_s`) = the explicit, duration-aware Phase-2
  signal (epic #415). **#427's reward sources speed from THIS term, never from the MSE.**
- A **LARGE MSE is a PASS** for the automation. The frozen 6-feat live mover (T3.2) has a standstill
  attractor and will not track a highway, so its `rmse_xyz` will be poor — and that is fine: #428
  proves the *measurement* is automated, objective, and velocity-aware, **not** that the bot is good
  (quality is the RL job, #427). `degenerate=true` flags a stalled run whose MSE is not meaningful.

## The geometric pin (the keystone)

The engine's `[moveprobe-handoff] slot N ENGAGED|DISENGAGED` log carries the engaged **window** but
**NO highway id and NO coordinates** (frogbot-moveprobe-handoff.patch:101-102 — slot + state only).
So `route_eval.py` pins the driven highway **purely from geometry**: over the `route_class=='base'`
highways, the nearest by **mean point-to-polyline (xy) distance** to the bot path — the offline mirror
of the live C primitive `mhw_nearest_base_highway` (`experiments/ktx_moveprobe/live/move_highway.{c,h}`).
No engine change, no manual index→id step. It reports `pin_margin_qu` + an `ambiguous` flag +
`off_all_highways` (the nearest is still beyond `R_OFF` on average → low confidence).

## PR2 — 4 bots / 4 routes (shape-A: N bots in ONE server)

PR2 ships #428's measurement spine for **N bots scored per-route in a single server/MVD** — **no engine
rebuild** (all per-slot cvars already exist on origin/main; `frogbot-moveprobe-perslot.patch`).

**What PR2 ships vs defers (read this).** SHIPS: the offline per-route scorer (`evaluate_run_multi`),
slot→player binding, `player_contact`, START-seeding, and the **enforced directed-run contract** below.
DEFERS (owner-gated follow-up): the **live** directed 4-route run, because no base-highway END maps to a
known live marker index offline — the `end_marker` map is **empty today** and a directed `--score`
therefore **fails loud (exit 2) before standing up the server**. **What PR2 does NOT prove:** that a
live `--bots 4 --score` run engages all four assigned routes — it cannot, until the FBMARKER dump fills
the markers. The score itself stays honest regardless: `pin_driven_highway` reports the highway the bot
**actually drove** and fail-closes on contamination, so a wrong-route or no-engage bot yields an
**invalid** (not a mislabelled) result, never a silent wrong number.

- **Assign by seeding + goal-pin (BOTH intents).** The handoff gate is **intent-first** — a base
  highway latches only when the bot has a goal within `MHW_R_GOAL` of that highway's **END**
  (`experiments/ktx_moveprobe/live/move_highway.c`), so spawn-snapping the START alone does **not** latch
  it (memory `route-eval-engagement-gate`). A directed `--bots N --score` therefore emits, per bot,
  BOTH `k_fb_moveprobe_spawn_origin_s<edict> "<x y z>"` (the START — 3-D `start_xyz` from
  `data/catalog/route_canon.dm3.json` via `route_eval.base_highway_seeds`; the generated 2-D
  `route_canon_dm3.h` is **not** the seed source) AND `k_fb_moveprobe_fixed_goal_s<edict> <marker>` (the
  END — a 1-based live marker index from `route_eval.base_highway_end_markers`), under **`k_matchless
  1`** (a marker index is meaningful only in the 65-item matchless set; `run-ledger.md:11`). If any
  assigned highway's END marker is unknown (all 4 today) the run **fails loud (exit 2)** as above.
  `edict = slot + 1` (slot 1 = bot edict 2; the spectator edict 1 is never seeded). **`end_marker`
  contract:** it is an **optional** per-base-highway field of the route-canon, populated by the
  follow-up at the generator **source** `data/catalog/route_canon_marks.dm3.json` + regen — the
  generated canon is **never hand-edited**. The 4 base highways map 1:1 to 4 bots — so `--score`
  requires **`--bots ≤ 4`** (a clear error otherwise):

  | slot | edict | highway (route_class=base) | seed `start_xyz` |
  |--|--|--|--|
  | 1 | 2 | `ra_tunnel_mega_rl` | `192 -208 -176` |
  | 2 | 3 | `enter_ra_mid_ledge_top` | `249.5 -315.9 68.8` |
  | 3 | 4 | `low_bridge_stairs_ya` | `1672.5 -75.9 -154.2` |
  | 4 | 5 | `rl_high_bridge_window_lifts` | `1520 432 -87.2` |

- **slot→player binding** (`route_eval.bind_players_to_seeds`). KTX `addbot` names bots **randomly**
  (not per-slot), so the binding is **geometric**: each seeded slot takes the **distinct** player whose
  trajectory passes nearest its spawn-snap coordinate (greedy by distance, uniqueness enforced; the 4
  base starts are ≥270 qu apart → unambiguous). The non-moving spectator shim (`KomodoPrewar`) is
  excluded by name (movement can't distinguish it — the frozen mover stalls too).

- **player_contact — the fail-closed cross-bot guard** (`route_eval.detect_player_contact`). Player
  collisions are ON; a **VALID** bot is demoted (`player_contact`, no consumable score) if **any other
  bound bot's** player **hull** overlaps it **during that valid bot's scored window** — checked against
  ALL bound bots, **including invalid-but-bound** ones (a bot that never engaged / multi-span still has
  a body that can block a valid bot; the invalid bot has no score so it is never itself demoted, but it
  CAN contaminate a valid one). Contact is hull-based (`|dx|<32, |dy|<32, |dz|<56` — NOT a centre-sphere
  distance; bots block on ramps/stairs with vertically-separated origins) and **continuous** (a swept
  AABB test over each linear sub-interval between the bots' recorded tick times, clipped to the other
  bot's recorded extent — a fast pass-through can't slip through a coarse grid, and a bot is never
  phantom-placed outside its recording). A physics block perturbs the scored path without disengaging
  the gate, silently corrupting the MSE — score **integrity, not yield**. (Route reality: `enter_ra_mid_ledge_top` is geographically isolated;
  the three east routes converge near RL — min closest approach **2.4–9.5 qu** — so that is where
  contact can happen if two bots traverse simultaneously. With the frozen standstill mover, bots mostly
  sit at their far-apart seeds, so contact is unlikely in practice.) Disabling engine combat /
  player-collision is **approach (b)** (a KTX change) — deferred; PR2 guarantees integrity via
  `player_contact` + `multi_span_engagement` instead.

- **Per-bot ledger shape** (`route_evals`). The ledger row carries `route_evals: [block, …]` (a
  single-bot run is a 1-element array). **No live consumer reads it yet** (the dashboard
  `BotAttemptsGallery.tsx` reads the row's required keys only) — so it is producer-only and **not added
  to the golden `bot-attempts.example.json`** (an example no test validates is not a contract). The
  per-bot artifacts (`route_eval.s<N>.json`) are the durable record; wiring `route_evals` into the
  dashboard (+ a panel-test + a golden-example row) is a separate consumer ticket.

- **Restart model.** The unit is the **run** (one ~90 s headless run, all bots, one MVD), scored
  post-hoc — no mid-run restart / chase-back / respawn-to-seed. A bot is seeded **once** (the
  spawn-snap is a one-time latch); if it leaves (wanders, is bumped, or dies → random respawn in FFA
  warmup), the existing rules invalidate **that bot's** score (`player_contact` / `multi_span` /
  no-engage), and you simply **re-run** a fresh seeded attempt. Headless runs are cheap → re-attempt is
  the recovery, not in-run rescue. The per-slot `fixed_goal` END-pin **is emitted** by a directed run
  (the intent-first contract above), steering a seeded bot toward its highway END; the **deferred** piece
  is the live END→marker map (until it lands, a directed run fails loud rather than runs un-pinned). A
  wandering bot is still invalidated or scored-against-the-highway-it-drove, never silently wrong.

## Re-score a recorded run (standalone)

```bash
python3 experiments/route_observatory/route_eval.py \
    experiments/prewar-movecheck/<run_id> --slot 1 [--player <botname>] [--grid arclen|time]
# -> "<run_id> highway=<id> rmse_xyz=… speed=…qu/s prog=… degenerate=…  watch=/demos/online/<name>.mvd"
```

`--player` is the bot name from the server `status` line; the default auto-picks the most-moving
player (the bot in a 1-bot prewar run). `--grid arclen` (default) scores path shape (speed-blind);
`--grid time` is timing-sensitive. `--no-write` prints the artifact without touching the run dir or
the ledger.

## Read it right (the engaged window — a PR1 approximation)

The handoff line has no clock, so `route_eval.py` maps the ENGAGED span from the `[moveprobe-live]`
cumulative total-frame counter onto the trajectory's own seconds clock (anchored fraction). KTX emits
the `[moveprobe-handoff]` line **before** the same-frame `[moveprobe-live] live=L/T` line, so each
transition is anchored to the **following** live counter (the engage/disengage frame), not the prior
(fallback) one. This is a PR1 approximation; the **rigorous sub-frame / variable-dt alignment is the
deferred #428 item**. For the plumbing close (a large MSE is a PASS) it is sufficient.

**A VALID run has exactly ONE ENGAGED span**, so `engaged_window_s` is a single contiguous `[t0,t1]`
and there is no gap to bridge. If the bot engages → DISENGAGES → re-engages (`n_engaged_spans > 1`),
the run is `valid:false`/`multi_span_engagement` (fail-closed — scoring across the gap would bridge
velocity/arclen; per-span scoring is a deferred follow-up). `n_engaged_spans` is always reported.

Eyeball the recorded path against the rendered route image (memory `headless-visual-self-validation`)
as a second channel. With the gate on, freshness `< 1.0` is **by design** (it measures the
engaged/on-highway share), not a defect.

## Deferred / YAGNI (named, not silent)

- **Engine combat-off / player-collision-off + a per-slot highway-PIN cvar** = **approach (b)** (a KTX
  change). PR2 took **approach (a)** — start-position seeding + the geometric pin (which *reports which*
  highway each bot drove) + the fail-closed `player_contact` guard — so it guarantees score *integrity*
  (a contaminated run is invalidated, never silently scored), not run *yield*. (b) would raise yield by
  forcing distinct routes + truly collision-free isolation; deferred until yield demands it.
- **Goal-pin per slot** (`fixed_goal_s<edict>` at the highway end) — steer a drifting bot back onto its
  assigned route by Commander intent, improving per-highway coverage. Needs an end_xyz→live-marker map;
  integrity-safe to defer (wander → invalid or scored-against-the-highway-it-drove, never wrong).
- **Dashboard `route_evals` wiring** — read the per-bot array in `BotAttemptsGallery.tsx` (+ a
  panel-test + a golden-example row, moved together). Producer-only until then.
- **Per-span multi-span scoring** — score each ENGAGED span on its own (or stitch them gap-aware)
  instead of fail-closing `multi_span_engagement`. Named follow-up.
- **Band-tolerant adherence** (#421 `route_canon_bands.dm3.json`) — grade "within the empirical band"
  rather than distance-to-centerline. Named follow-up.
- **Rigorous variable-dt alignment** (a DTW-style alignment) — PR1 reuses the proven arc-fraction +
  time grids; defer until the RL loop shows them insufficient.

## What this does NOT prove (scope boundary)

- **Not** that the bot moves *well* — quality is Phase-2 RL (#427). A large MSE is expected + a PASS.
- **Not** a believability-band judgment — scored vs the **one** #420 seed line, never the #421 band.
- **Not** the rigorous trajectory alignment — arc-fraction MSE is path-shape-only / speed-blind.
- **Not** the v5 live encoder — the live seam still drives the **6-feat** mover (T3.2 Branch C); the
  v5-live bridge is a separate ticket.
